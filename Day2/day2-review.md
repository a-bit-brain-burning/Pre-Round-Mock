## A · 先数清一个输入元素参与几个窗口

- `784³` 的窗口边长为 5，步长为 2。相邻窗口共用输入，warp 可以保留几行部分和，再加入新进入窗口的值。结合 `float4` 连续读取、相邻线程交换边界值和按尺寸选择窗口数，该组从 v3 的 902.336 µs 降到 v45 的 645.856 µs。v45 在五个尺寸上的耗时依次为 22.496、34.608、159.616、645.856、1209.952 µs。[完整计算源码](1/code.cpp)
- `512³` 和 `1024³` 的窗口边长与步长均为 3，各窗口互不重叠。沿连续的深度维度一次读入整行，再合并九行数据。一次独立 H20 诊断中，`1024³` 的池化耗时 1211.456 µs，同规模连续读写为 1214.432 µs；`512³` 对应 157.280 和 156.608 µs。缩短求和指令序列对这两组的优先级较低。[显存读写对照](1/pool-traffic.cu)
- 小尺寸单独选分块。用四份输入轮换测量后，在正式提交 v38 中，`192³` 和 `224³` 分别从 v32 的 23.936、35.264 µs 降到 22.080、34.256 µs。对 `784³` 更改 CUDA Graph 启动方式，两次正式结果仅相差 1.024 µs。相邻版本的微小差距需要复测。[小尺寸分块](1/pool-small-tuned.cu) · [启动方式实验](1/pool-graph.cu)
- 连续视图也可能从第二个 FP32 元素开始。将输入和输出起点均移动 4 字节，`784³` 的通用实现耗时 10804.704 µs；按 FP32 连续读取并在共享内存合并深度窗口后为 2035.424 µs。本机另检查了 4、8、12 字节三种起点及输出两端的哨兵。正式回执未给出设备指针地址。[视图实现](1/pool-views.cu) · [验证程序](verify-views.py)

## B · 归约维度、输入变化与输出成本

- 随题参考按每个通道的 `(B,D1,D2)` 计算总体方差。样例首个位置预期约为 0.886794，仅沿 `B` 计算约为 0.999995，可以借这一个位置区分两种读法。验证还覆盖常量、很大均值下的小方差、单一异常值及大幅值输入。[题目与接口](2/problem.md) · [PyTorch 和 FP64 对照](verify.py)
- 大通道使用分段统计，合并部分和后直接归一化；小通道可以把数据留在寄存器，一次 kernel 调用完成归约和输出。在队内两次提交中，第 3 组从 43.936 降至 32.352 µs。后续对照中，完整计算入口为 567.536 µs；通道分批、四个线程块组成 cluster、TMA 批量传输分别为 896.480、1194.304、1032.448 µs。将输入搬入共享内存的成本需要由实际复用次数补回。[通道分批](2/bn-group.cu) · [cluster 实验](2/bn-cluster.cu) · [TMA 实验](2/bn-bulk.cu)
- 在输入可以改写的情形下，b5 和 b6 逐位检查数据并按通道还原输出。每组只修改一个元素时，按通道重算将四组诊断中位数之和从 2115.392 降到 755.680 µs；输入完全相同时分别为 638.560 和 640.320 µs。少量改写和输入不变需要分别计时。[按通道更新](2/bn-channel-cache.cu)
- 单独测量 FP32 读入、写出、当前输入的归一化，以及当次结果的编码与解码。前两组各有 67,108,864 个元素，单组仅写出 FP32 就有 256 MiB。独立 H20 写出测试分别为 73.792 和 73.312 µs。题面中的 `1e-5` 是方差公式里的 epsilon。已取得的分数无法确定评测的绝对和相对误差门限。
- B 的 1272.0254 分与 1275.0428 分对应同一份源码，总耗时相差 0.720 µs。1297.9642 分版本的四组用时为 113.136、113.024、16.000、56.000 µs。按本场计分换算，1500 分需要约 258.001 µs，距该纪录仍差约 40.159 µs。

## C · 一次读取服务四个相邻输出

六组输入由两种图像尺寸与三种窗口边长组成。v1 沿列滚动更新竖直和，再用共享内存中的前缀和求水平方向结果，总计 225.728 µs。v2 连续读取 128 列，复用中间 96 列的水平窗口和，用时降至 157.392 µs。v3 改为在寄存器中保存移出窗口的像素，总计 137.024 µs。v4 的每个 warp 处理连续 96 列、12 行，每个线程一次读四列。四个相邻输出共用窗口中间的列和，各自补足两端，六组合计 118.272 µs，全部通过。[C 源码](3/code.cpp) · [图像尺寸与窗口](3/problem.md)

图像边缘的除数是有效像素数。A 的零填充则始终除以完整窗口体积。两题可以共享连续读取和滑动求和的方法，各自的边界算式需要独立测试。窄图、单行、图像小于窗口、首地址移动一个元素这四类样例，都能检验常规大图覆盖不到的路径。

## 正式初赛的五个对应实验

下面的输入形式来自工作区的五题预研。表中列出待验证的正式题用法；Day2 的分数和 H20 时间只属于三道模拟题。

| 正式题 | 可以复用的 Day2 方法 | 在正式接口上如何验证 |
| --- | --- | --- |
| SwiGLU backward | 借用 C 的寄存器复用。对于 `Y=SiLU(A)·B`，一次读取 `A、B、G`，复用 `sigmoid(A)` 同时写出两份梯度。若每项都是 BF16，基本流量为每元素三读两写、共 10 字节。 | 分别用 autograd 核对两份梯度；覆盖大幅值、尾部元素及不同起始地址。用相同输入、输出字节数做读写对照，再判断是显存带宽还是指数计算限制速度。 |
| Sink attention | 借用 B 的分段归约和 A、C 的输入块复用。在寄存器中保存每行的最大值、按该最大值缩放的分母与加权 V 和；下一块改变最大值时，同时缩放旧分子、分母。 | 用短序列的高精度稠密参考核对 causal 和滑动窗口边界；依据正式 sink 定义检查它对分母和输出的贡献。不能用普通滑动窗口均值代替注意力权重。 |
| Batch-invariant GQA | 将共享 K/V 的查询头编在一起，复用 A、C 的“同一输入支持多个输出”。借用 B 的部分统计合并方法，为同一请求固定序列分段与浮点合并次序。 | 比较同一请求单独运行、与长短请求混批、改变批内顺序时的输出。核对变长序列的起止位置，按正式要求分别检查逐位一致性与数值误差。 |
| ISA indexer | 借用 B 在通道内保留部分和、最后一次写出的思路。若接口按多个头计算候选分数，可让每块累加同一批候选的跨头贡献，减少中间评分数组的写入。 | 用小输入分别核对点积、激活和跨头合并次序。若正式接口还要求选择前 k 项，再检查有效范围、同分次序及候选编号；若只输出分数，则应完整写出。 |
| FP8 MoE | 借用 A、C 的分块复用与 B 的分阶段计时。将同一专家的 token 放在一起复用权重和 scale，分别测量重排、专家计算和按 token 合并，最后再测整次调用。 | 用空专家、每个专家少量 token、路由集中到一个专家三种输入，对照高精度逐 token 参考。核对 FP8 格式、缩放粒度及路由接口。记录节省的权重读取是否覆盖重排和写回成本。 |

Day2 按各组总耗时计算本场成绩。正式初赛按每个用例相对标程的加速比计分，逐例封顶。迁移时应保留每一组的耗时、数值检查与得分贡献，再决定是否针对该尺寸单独优化。
